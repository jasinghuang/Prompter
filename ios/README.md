# 提词器 · iOS 原生版

SwiftUI 界面、SwiftData 本地存储、TextKit 2 / CADisplayLink 提词引擎。Web PWA 与 iOS 各自构建；iOS 保留原来的黑金配色、细金边卡片和胶囊控件。

## 构建

最低系统 iOS 17.0。安装 Xcode 和 XcodeGen 后：

```bash
cd ios
xcodegen generate
open Prompter.xcodeproj
```

工程由 `project.yml` 生成。真机运行需在 Xcode 中选择自己的签名 Team；模拟器可以关闭签名构建。

## 本地语音跟随

播放页打开设置，在「提词模式」中选择「语音跟随」，再选择识别引擎。当前是四引擎对照版：Apple 本地、Zipformer 流式、SenseVoice 分段，以及原 Paraformer 流式。单次只运行一个识别引擎，共用采集、Silero VAD、原稿匹配和滚动定位。默认仍是「匀速」，旧设置的识别引擎仍为 Paraformer，原有速度设置独立保留。音频不录制、不写日志、不上传。

对照版内置 Paraformer 约 237 MB、Zipformer 约 167 MB、SenseVoice 约 240 MB 和共享 Silero VAD 约 0.64 MB，手机无需连接模型下载站。模型选择后将另行精简测试包。Apple 不内置 ASR 权重，但首次可能需由系统下载中文语言资源，不能将它描述为不占设备空间或零发热。iOS 26 及以上优先使用 SpeechAnalyzer/SpeechTranscriber 的本地快速增量结果，时间范围用于合并逐词结果和替换临时修订；不支持时仅允许显式支持离线的 SFSpeechRecognizer 路径，设置 requiresOnDeviceRecognition=true，不回退云端。

- 轻点正文才请求麦克风权限并开启监听，识别文字匹配当前位置附近的原稿后平滑滚动。语音模式隐藏手动速度滑杆，按实际读到的位置和最近语速跟随。
- 对齐结果只更新目标行的 Y 偏移，同一行内的识别字不改变目标位置。CADisplayLink 按现有位置追赶、最低速度与最终速度缓冲逐帧输出，继续保留已真机确认的即时响应、约 2 秒变速过渡与约 6 秒停顿减速；匀速模式保持原逻辑。语音模式竖屏使用无标记的中上方阅读区（上方三分之一），横屏以镜头中心高度为阅读基准。
- 横屏前台使用 App 绘制的独立指示环：固定金色底轨、随实际阅读位置推进的绿色弧段、有声且最近 1.5 秒对齐有效时的音量辉光。三层共用顶部中点顺时针路径，音量只改变柔光亮度，模糊半径固定以保留渲染缓存，不缩放轮廓，不镜像镜头指示。竖屏、离开播放页、设置/镜子打开时隐藏；暂停保留静态进度，停止语音脉冲。稿尾完成仅表示读稿结束，不代表视频录制成功。
- 指示环使用 UIWindow 实际坐标，由窗口场景方向确定镜头在横屏的哪一侧，安全区用于筛选适用设备。iPhone 16 Pro 使用 Apple 尺寸图建立初始基准（https://developer.apple.com/download/files/accessories/dimensional-drawings/iphone-16-pro.pdf）；其他灵动岛机型使用待校准基准，不宣称读取系统私有轮廓。设置中的“调整与灵动岛的贴合”可微调位置/长宽；校准保存在本机按机型区分的 UserDefaults 中，不随稿件设置导出。
- 音量复用现有唯一麦克风 tap，通过带采集代次的线程安全邮箱以 20Hz 发布显示包络，脱离 ASR 推理队列；约 55ms 升起、320ms 回落。视觉还检查采样新鲜度 250ms 与当前 VAD/匹配有效性，静音的滚动惯性不会伪装成说话。旧 ActivityKit 控制器、Widget 扩展、配置和旧 RMS 语音门限辅助类型已从正式构建移除：标准实时活动在 App 前台不提供所需的常驻镜头轮廓。
- 2026-11-11 实机确认的原始基线保存在本地 Git 标签 `stable/ios-speech-island-2026-11-11`（`08a3576`）。性能修订在独立分支进行，不修改 `SpeechScrollMotion`、匹配/时序、阅读锚点与 `ScrollEngine`。辉光层使用局部图层边界和显式阴影路径，绿色阴影仅覆盖已读弧段；进度动画只在阅读位置变化时更新。竖屏、指示环隐藏、暂停或减少动态效果时停止音量显示计时；麦克风、VAD 和跟随判断继续按原逻辑工作。48kHz 转 16kHz 复用同步 PCM 缓冲，Apple 选择 16kHz 时跳过同格式转换，但交给原生异步识别的缓冲仍独立持有。详细日志仅 Debug 且显式传入 `-speechDiagnostics` 时写入，Release 不含诊断写盘。
- 共享 Silero VAD 判断语音（180ms 收尾窗口；近数字零静音有明确停止上限），不再用 0.004 RMS 音量门限阻挡轻声。原稿匹配只更新目标位置，已进入阅读区时不强制追完额外提前量。根据最新试读偏好，最终速度优先保持柔和：检测到速度趋势变化即开始微调，用约 2 秒平滑过渡（恒定输入约完成 95%），取消此前先等 2 秒的观察门槛；分批 ASR 的短促脉冲不会直接变成画面加速。突然加快朗读时的追赶会相应延后，原有 0.3 秒目标收尾授权不再代表最终画面必须在 0.3 秒内到位。按后续试读反馈，低速前进提高至每秒最多 32pt（上版两倍，细小行高按比例降低）：首次有效匹配后，说话期间保持最低滚动速度，不因追到当前 ASR 目标而停住；追赶与最低速度先合并，再经过最终渲染速度缓冲，不叠加速度。首次匹配用估计语速建立起步速度；后续变速直接使用临界阻尼的精确积分，兼顾 60/120Hz 一致性、速度与加速度连续性，不再叠加观察期和低通等待，换气后也不会重新等待 2 秒。停顿从当前实际速度起步，用约 2 秒降向慢速，再用约 4 秒缓缓降到零，不突然切回慢速。正常前置范围仍为已识别目标之后 1.6 行，长减速按当时速度留出最多 4 行的有限刹车空间，并提前减速避免撞到边界。说话期间的最低速度要求实时语音和最近 6 秒的有效匹配，启动等待、长时间匹配失败、输入检查、手动暂停及稿尾不启用；原生时钟还检查 0.65 秒语音新鲜度期限。续滚不推进匹配游标或假定未读文字已被识别。迟到结果不延长这段停顿窗口，稿尾不续滚；超过窗口完全停止。收尾与续滚上限由原生逐帧时钟执行。手指按下仍立即冻结并清零速度。只有新鲜匹配和近期语音才能授权收尾，噪声不能启动匀速盲滚。音频采集与识别仍有延迟。
- 语音跟随时轻触或拖动正文立即暂停跟随；全部手指松开 1.5 秒且惯性滚动结束后，以当前阅读区重置搜索窗口和识别流，丢弃旧识别结果再恢复。再次触摸会取消旧倒计时。右上角暂停键可持续暂停；打开设置或前置镜子、离开播放页及进入后台也会停止监听并取消自动恢复。真正开始的系统音频中断、录音设备切换、输入不可用或识别积压会暂停并显示对应原因，需要轻点重新开始；中断结束通知不触发暂停。
- 正常启动会延迟收到音频类别变化通知（iPhone 16 Pro 真机复现为 `categoryChange / reason=3`），不能仅凭通知就停止采集。路由/引擎配置通知先等待 250ms，再比较实际麦克风身份、采样率、通道数和引擎运行状态；同一输入且采集正常时继续。相同麦克风的格式变化或引擎自停会重建采集 tap，5 秒内最多恢复两次，避免无限重启。引擎通知只监听当前实例，并校验会话与采集代次，忽略旧实例的延迟通知。
- 音频会话由 `SpeechAudioSessionCoordinator` 按会话身份串行管理：iOS 27 使用系统异步 activate/deactivate，iOS 17–26 的同步调用和音频类别配置在专用队列执行。暂停立即更新界面并停止录音，再按顺序释放会话；激活尚未完成时暂停也会在完成后清理，旧会话的释放不能关闭新会话。
- 匹配忽略空白、标点和大小写/全半角差异，容忍部分漏字与口头语；增量识别采用替换语义，修订不会累加重复文字，也不会拖动屏幕倒退。脱稿或低可信结果不更新目标；暂时匹配失败时，只允许在仍有语音且最近匹配未过期时追赶此前确认的位置，不盲滚。回读上文时拖到目标位置，松手后自动重新定位并恢复。
- 「显示识别与跟随状态」可在本机显示最新识别、说话检测、原稿匹配和已识别行距阅读区的位置差；识别文字只保留内存，不写诊断日志。ASR 出字、对齐成功和画面到位是三个分别检查的状态。
- SenseVoice 是离线模型：发声后先累计约 0.8 秒，之后最多每 0.6 秒重复识别当前窗口，窗口约 6 秒时切段，并保留少量重叠；停顿收尾。这是分段快照识别，有等待成本，不能称作原生逐字流式。
- 保留关键词/空行的显式自动暂停，以及读完后的动作。自然停顿与手动暂停区分处理；识别到稿尾并收到最终结果后，等待已识别行进入阅读区或完成受限收尾，再执行读完动作，避免刚识别完就先停止滚动。

模型内容固定为 Hugging Face 仓库 `csukuangfj/sherpa-onnx-streaming-paraformer-bilingual-zh-en` 的版本 `8e40c43232a1c5c66c82111efc5820d3accca11b`。Mac 构建脚本和手机备用下载均优先使用 ModelScope 社区仓库 `pengzhendong/sherpa-onnx-streaming-paraformer-bilingual-zh-en` 的固定提交 `c9d662eca7ca87765078148501659faa24e842ed`，三个文件的大小和 SHA-256 与原发布一致；网络、HTTP 或内容校验失败时再使用原 Hugging Face 固定版本。来源与优先级统一定义在 `ParaformerModel.downloadBases`，取消操作不会触发备用下载。

构建脚本只准备 `encoder.int8.onnx`、`decoder.int8.onnx` 和 `tokens.txt`，逐文件校验长度和 SHA-256，写入固定版本的完成标记后作为 `ParaformerModel` 资源文件夹打包。运行时优先直接读取已签名 App 中的完整模型，不另复制一份到手机数据目录。模型文件被 Git 忽略，首次构建在 Mac 上下载；已有校验过的本地资源或 `ios/build/speech-fixture/` 缓存时不联网。也可预先运行 `python3 ios/scripts/prepare-speech-fixture.py --bundle`。`zhaochaoqun/sherpa-onnx-asr-models` 本次只核验到聚合压缩包条目，未验证其解包内容，不作为默认来源，也不称作官方同步镜像。

仅在缺少完整内置模型的特殊构建中保留下载入口作为备用：显示实际接收的 MB 数，区分连接、下载、校验与安装，支持取消和重试。备用下载逐文件校验后整套安装到 Application Support，不完整下载不能启用，下载模型不进入设备备份。手机访问 Hugging Face/CDN 超时或断网时显示中文错误；标准构建无需走这条链路。

`project.yml` 固定 sherpa-onnx SPM 依赖为 `1.13.8`（ONNX Runtime `1.28.2`），Xcode 首次构建会获取框架。核心边界：`SpeechModelStore` 管安装与校验，`SpeechModelDownloader` 使用 session 级 `URLSessionDownloadDelegate` 收取实际字节进度（不用 async download 的 task delegate），`SpeechRecognitionPipeline` 串行处理音频和推理，`SpeechScriptMatcher` 对齐原稿 UTF-16 位置（容忍中文同音字；长段前缀出错时，仅允许最近 8 字以高置信度在前方 24 字内重新对齐），`ScrollEngine` 逐帧跟随。下载连接或传输 20 秒没有新数据时超时并显示重试提示。用两条 CPU 推理线程，限制音频积压，避免识别队列无限延迟。

普通单元测试覆盖模式迁移、匹配/修订、停顿和变速、权限取消竞态、流式重采样及滚动冻结。需要执行真实模型推理和下载集成测试时，在仓库根目录先运行：

```bash
python3 ios/scripts/prepare-speech-fixture.py
```

脚本下载并校验同一版本的三个模型文件和官方样例音频到被 Git 忽略的 `ios/build/speech-fixture/`。准备此目录后，`SpeechFollowTests` 会额外执行真实 INT8 增量解码、断句和 App 下载/安装路径测试（后者会再次联网下载模型）。未准备时只跳过这两项集成测试。模拟器验证不能代替目标 iPhone 麦克风、口音、距离、AirPods 路由、发热和耗电实测。

## 稿件列表与滚动

列表由 `NativeScriptList` 使用系统 `UITableView`、diffable data source 和原生滑动操作承载，卡片仍为原有 SwiftUI 黑金样式。分类标题与稿件共用扁平行序列，稿件跨分类保留全局 UUID；标题是不吸顶的普通行。搜索展开与键盘焦点由独立的 `ScriptLibraryControls` 管理；进入编辑或播放时取消待执行的自动聚焦，返回时保留搜索词但不自动抢回键盘。计数和全选复用当前投影中的可见稿件 ID，空搜索取消不重复发布相同查询。列表顺序和卡片内容使用同一批不可变 `ScriptSnapshot`，卡片不直接观察正在变更的 SwiftData 对象。原生 `didEndEditingRowAt` 之后才提交滑动操作；发生跨分类或置顶重排时一次性重建原生行高，保留未变更的可见行位置，避免移动中的行同时重算尺寸。普通内容变更只重新配置相关行，渲染更新串行合并；筛选/排序变化会先关闭已展开的滑动操作。卡片没有横向 `DragGesture`，竖向滚动继续由原生表格仲裁。

- 标题栏“新建稿件”使用金色药丸文字按钮；搜索框默认收起，点击排序旁的放大镜在当前筛选行展开并聚焦，不额外占一行；取消会清空搜索并收起。下一行左侧使用原生收纳菜单选择全部、星标或文件夹，右侧保留上下箭头排序入口。列表只展示“待拍摄”和“已拍摄”两个分类，星标稿件在各自分类内置顶，不单独生成星标分类；分类篇数包含其中的星标稿件，空分类隐藏。排序依据为时间（最近修改）、标题、字数，并分别提供升序/降序；在每个分类的星标和普通稿件中分别排序。卡片外观与直接操作保持原样。
- 平时列表延伸到屏幕底部，原生表格保留底部安全区的滚动余量，避免固定黑边截断卡片；撤销或批量操作栏出现时，列表让出操作栏空间，保证末张卡片可以完整滚到操作栏上方。
- 左滑揭示“删除”，删除后保留 8 秒撤销；关闭 full swipe，降低误删。
- 右滑标记/取消已拍摄；已拍稿件沉到对应分层。
- 点正文开始提词；编辑按钮独立于正文按钮；底部按日期、字数、时长、文件夹、星标排列，文件夹和星标可直接点击；左右滑动提供拍摄标记和删除。
- 长按进入多选，底部操作栏支持全选、移动、批量删除。
- 播放页左侧依次展示返回、时间状态、前置镜子；右侧依次展示拍摄标记、设置；轻点正文播放或暂停，底部仅保留字号和速度参数；速度按 1 字/分调节；窄屏分两行且滑杆等长、左右对齐，宽屏并排且速度滑杆更长。点击左上时间回到顶部并暂停、计时归零，读完后在时间下方提示该操作。
- “读完以后”使用与自动暂停相同的分段选项：停在末尾、回到开头、标记并返回。仅卡片左滑出现的删除操作使用主题金色；顶部清空、批量删除及确认按钮保留危险操作红色，确认和 8 秒撤销流程保留。

## 保存、删除与撤销

- 编辑器提供“完成”，同时在文字变更 500ms 后和进入后台时保存。
- 新建稿件的多次自动保存复用同一条记录；没有修改的稿件不更新时间。
- 删除使用 `Script.deletedAt` 内部标记支持短时撤销及旧库兼容；不提供最近删除页面或恢复入口。
- 底部撤销提示保留 8 秒，只撤销最近一次单篇或批量删除。撤销和多选操作条只在对应状态下出现，列表没有常驻底部菜单。
- 旧库兼容所需的内部删除标记保留，后台清理过期标记记录；界面不承诺长期恢复。
- 编辑器直接展示拆分方式和自动暂停；“智能拆分”与拆分方式同一行展示，按钮只显示操作名、不显示篇数；点击后保存当前内容、创建片段并替换原稿，无预览或二次确认；列表不保留原稿。
- 重要数据写入显式保存并反馈失败；存储打不开时提供重试，保留原存储文件。

## 列表入口

顶部保留清空全部和新建；清空需要确认，可在 8 秒内撤销。没有常驻底部工具栏或最近删除页面。“全部稿件”／当前范围右侧直接展示 `square.and.arrow.up` 导出图标，再往右是搜索和排序；菜单和多选栏不再放传输入口。多选时仍用同一个导出图标导出选中的稿件。接收方直接用提词器打开 `.prompter` 文件导入，列表不设置导入按钮。

## 两台手机间的稿件库传输

- 原生 `.prompter` 文件使用版本化 JSON，保留稿件 UUID、标题、完整正文、单层文件夹归属、星标、已拍摄状态和创建／修改时间（毫秒）。文件夹清单与稿件归属一起校验；当前文件夹由稿件推导，不额外承诺空文件夹或多级子目录。设备设置、AirPods 校准、内部删除标记不属于传输内容。
- 导出支持全部稿件、当前范围（文件夹／星标）及多选稿件。系统分享面板使用 `FileRepresentation` 传输实际附件，可用于 AirDrop 等方式；也可直接存储到“文件”。临时导出文件保留供异步分享读取，下次导出时清理超过 24 小时的临时文件。
- `UTExportedTypeDeclarations` 与 `CFBundleDocumentTypes` 注册文件类型，`onOpenURL` 接收外部打开的文件；没有独立的手动导入入口。冷启动时文件先读入内存队列，数据库就绪后展示确认；正在编辑或播放时不强行关闭当前工作，返回列表后处理。一次最多保留 4 个正在读取／待处理文件。
- 解析与编码在后台执行；外部 URL 使用协调读取和匹配的 security-scoped access，读取上限为 10 MB，单文件上限为 10,000 篇。未知格式版本、损坏内容、重复 UUID、无效时间或不一致的目录引用会在写库前拒绝。
- 导入预览区分新增、完全相同、同 UUID 有差异。默认保留本机差异稿件，用户可明确选择使用文件版本；正文相同但 UUID 不同的稿件仍视为独立稿件。同 UUID 的本机删除记录也算差异，只有明确选择文件版本才恢复。
- 写入前重新核对预览涉及的本机记录，变化后要求重新确认；整批一次保存，失败只恢复本次触碰的旧值并移除本次插入，不回滚无关编辑。导入成功后清除旧撤销条，避免旧删除快照覆盖刚导入的状态。本机其他稿件保留。
- `MigrationService` 继续单独保留旧 PWA JSON 的解析与迁移语义；本次文件入口只接受 `.prompter`，不把任意 JSON 文件关联给 App。

## 动效与反馈

第一批语义动效使用 `Theme.swift` 中的 `AppMotion`：按压 150ms、播放控件淡变 200ms、工具条/临时提示进入 180ms 与退出 160ms、校准文字淡变 140ms、同阶段真实传感器进度平滑 100ms。这些是项目参数，不是系统强制时长。普通按钮轻缩放至 0.98，大稿件卡片只轻淡化，系统按钮保留原生反馈。

- 播放引擎立即启停；右侧操作区、底部参数和阅读引导线只动画透明度。隐藏控件立即退出点击及辅助功能树，避免隐形控件阻挡阅读。
- 撤销和多选工具条单独淡变。退出任务可取消，退出时立即禁用点击；连续删除只更新最近一批的数量与撤销数据，不重复进场。8 秒撤销期限不因淡出延长。列表行高、安全区尺寸、数据更新和重排不进入动画事务。
- 字号提示容器只进场一次，捏合读数即时更新；暂停原因与播放时的连接异常轻淡变。暂停时连接状态由原有 AirPods 状态区说明，不再叠加相同浮层；点头开始/暂停仍不显示 Toast。
- 校准每次手动开始/重试仅给一次准备好触觉，自动重新准备不反复震动；单步记录采用轻选择反馈，只有独立验证通过才给成功反馈。阶段变化或进度回退立即重置，仅平滑同一阶段的真实前进；动画不参与传感器判断。
- 以上自定义反馈遵循“减少动态效果”，关闭缩放、文字淡变和进度平滑，控件状态即时切换；功能性提词滚动不受影响。

第二批补齐局部反馈与取消行为：

- 横屏设置使用统一的 220ms 进出与取消时的弹回。拖动在固定容器坐标里计算，面板与遮罩直接跟手；手势取消可复位，滑杆不参与抽屉拖动。竖屏继续使用原生 sheet。关闭后的延迟重置任务已移除，重开时立即清理旧偏移。
- 前置镜子与操作引导各自在独立图层淡变，不再给整个播放页附加镜子开关动画。镜子清理无独立插入/移除节点的缩放声明，摄像头实际报告就绪后，预览与加载层做 140ms 局部淡变；预览层转屏仍禁用隐式 frame 动画。
- 播放页已拍摄按钮保持 44pt 占位，只对图标填充和颜色做 140ms 状态过渡；取消标记对称，不增加图标弹跳。
- 编辑器关键词字段、设置关键词字段和文件夹创建表单只对自身做 160ms 轻淡入。布局和输入能力立即生效，退出模式时释放对应焦点，不保留可输入的隐藏字段；正文、自动保存与系统键盘不附加新动画。
- 横屏操作提示的确认按钮放在说明下方，避免与末行文字重叠。从设置查看操作提示时，竖屏等待系统 sheet 的 onDismiss，横屏等待抽屉退出完成，再显示引导；重新打开设置或离开页面取消待显示请求，避免使用固定等待时长或叠两层面板。
- 播放页已改为 `NavigationStack.navigationDestination` 推入，返回按钮、边缘拖动和“标记并返回”共用原生导航返回。`NativePlayerNavigation` 在自定义顶栏下启用系统交互返回，支持短拖取消、长拖完成；只在当前播放页且无设置、镜子或引导时允许开始。退出后恢复系统手势的原委托及启用状态，正文中的旧 24pt 关闭识别器和镜像边缘映射已移除。文字镜像不改变物理左边缘方向。
- DEBUG 的 `-openPlayer` 只在一次列表会话首次进入时执行，避免导航返回列表后自动再次打开。功能滚动、无动画列表重排和原生系统控件维持原有规则。此前的第二批导航录屏是迁移前对照，最新正式实现与验证见 `build/motion-final-2026-11-02`。

字号等设置在内存即时生效，持久化合并为 300ms 一次；退出编辑和进入后台时立即写入。编辑器与设置面板绑定同一个暂停配置，空关键词模式也能正确保留。

## 验证

### AirPods 点头控制

播放页设置中提供开关，默认关闭。首次开启依次校准低头、抬头、左右歪头、左右转头，随后在最后一步记录三次自然点头，再用一次独立点头验证后保存。可选择“使用默认并验证”跳过个人适配，无需重做六方向。歪头指脸仍朝前、耳朵靠近同侧肩膀，转头指脸朝向左右两边；不要求耳朵碰到肩膀。取消首次校准不会开启；重新校准取消时保留原配置。更换耳机后识别不顺手时，用户可自行选择重新校准。校准记录舒适动作幅度和耳机坐标轴，不是颈椎活动范围的医学测量。

- 原生 `CMHeadphoneMotionManager` 提供融合运动数据；只在播放页符合条件时监听。设置、化妆镜、操作引导、后台与离开页面都会暂停识别；校准在首次点击开始后维持同一条运动流，直到退出或验证完成。动作之间只更换处理器，丢弃等待期间的动作样本，避免每步重启后数据源和参考坐标变化。
- `HeadMotion.swift` 是纯值类型算法。重力向量通过投影后的 `atan2` 计算有符号点头/侧倾角，不使用欧拉角，也不长期积分角速度。重力不能测偏航；转头校准用短时相对四元数和角速度，运行时用绕重力的角速度排除转头。
- 一次有效点头需要：约 0.45 秒稳定准备 → 至少 6° 低头 → 反向回正并短暂停留；候选约 0.26–1.85 秒内完成，低头段不超过 0.95 秒。六方向校准用于辨认坐标与舒适上限，不再以低头校准幅度的 45% 作为控制门槛（原先 46° 校准会要求每次控制至少 12°）。回正允许约 4–7° 的有限偏差，同时校验静稳端点与点头轴角速度占比。明显侧倾/转头、走动、碰撞、数据丢失及传感器切换仍否决候选。
- 待命基准允许有条件地重新定位：仅在 armed、没有点头候选时，角速度低于 0.12rad/s、用户加速度低于 0.04g，重力方向在约 0.8° 范围内连续稳定 0.65 秒后更新。单次变化不超过 8°、侧倾不超过 6°，相对本次进入待命时的基准累计不超过 12°；小于 1.5° 的微量跟随同样受累计上限约束。检测到低头即冻结，手动重置、缺帧、走动或传感器变化均重新准备。识别后的冷却准备新一轮基准，不改变持久化的六向校准轴。修复先抬高 5–8° 停稳、再小幅点头相对旧基准不足而漏判的问题。
- 点头幅度上限随已学到的舒适幅度变化，不再用固定 36° 上限否决较大点头。38° 起始姿态限制只检查中立基准，不能应用到点头全过程；否则已校准 46° 的动作依旧会在进行途中被清除。点头中的旋转会产生用户加速度，不再用单帧 0.12g 清除完整动作；保留 0.45g 碰撞门槛、静稳端点、原生活动分类、偏轴、节奏与数据连续性检查。触发后的 0.85 秒冷却同时收集静稳数据，不再等冷却结束才开始准备；点头触发播放切换不会再次调用手动重置。手动点击/拖动单独取消排队事件并抑制 0.35 秒，之后重新准备。
- 回正静稳窗口最多 200ms，仅累加两端采样都满足角速度 <0.35rad/s、加速度 <0.07g 的区间，累计至少 100ms；允许其中一次、采样估计累计不超过 40ms 的轻微扰动（角速度 <0.55rad/s、加速度 <0.10g），扰动和首次恢复区间均不算静稳，最后还须连续静稳至少 40ms。超过预算、第二次扰动或超出回正带会重新建立窗口；碰撞、走动、偏轴、传感器变化、非法值与真实缺帧继续中断候选。完整动作 1.85 秒截止和 6° 门槛不变，不延长动作来等待通过。诊断导出 `toleratedReturnDisturbanceMs` 为该次响应窗口容忍的扰动区间估计值。已有校准兼容，界面没有新增控件。
- 开启后播放页暂停时在左上显示真实待命状态（等待静止、就绪、等待回正、走动等），只有检测器已进入 armed 才显示已就绪；播放时收起常驻状态，避免遮挡正文。有效点头直接切换播放并提供轻触反馈，不显示开始/暂停文字浮层。设置、化妆镜和后台仍暂停识别。
- iOS 18 及以上且耳机支持时，同时使用原生 `CMHeadphoneActivityManager` 的步行/跑步分类作为额外否决条件。iOS 17 或不支持活动分类的耳机保留加速度、角速度、静止与节奏过滤；活动分类本身可能延迟，不能取代这些逐样本保护。
- 数据处理在串行后台队列执行，UI 只接收离散事件与低频连接心跳。运动样本不写文件、不上传，只持久化校准参数。失败候选输出一次本机结构化诊断（原因、峰值幅度、时长，不含原始采样），设置中保留上次失败原因，成功识别后清除；关闭设置或暂停识别不会抹掉这条诊断。连接中断不会切换播放状态；重连后重新等待静止。播放检测期间换耳或换耳机后沿用已有轴与个人设置，清空候选、滤波和静稳窗口，重新停稳后恢复；不强制重新校准，也不把来源变化报告成断开。六方向校准与最终适配采集期间仍保持同一来源，避免混合坐标。
- 设置里的“点头诊断”可主动开启本次测试记录，默认不记录。`NodDiagnostics` 将识别通过、页面实际切换、页面未接收、候选拒绝和服务异常分别统计。记录开启时逐帧检查状态，仅在状态变化时增加事件，补足 0.5 秒界面心跳之间的短暂晃动；等待静止、冷却、手动操作后重新准备等状态不自动算作漏判。校准与最终试点头不计入播放统计。
- 测试时先开启记录，关闭诊断和设置回到正文；未响应后可回到诊断手动标记，“上次是误触”仅关联最近一次已实际切换的点头，支持撤销。未响应标记保留进入设置前的最近观察状态和时间，只作参考，不断言为漏判原因。识别器不能知道用户的全部动作意图，界面和导出均不计算成功率。
- 诊断仅在本次播放页面内存中保留，离开页面后释放，不自动保存或上传；累计计数覆盖本段记录，事件保留最近 128 条、可撤销手动标记保留最近 32 条，最近实际响应单独保留以便关联误触。用户通过系统分享导出 JSON 文本，包含原因、状态估计时长、动作幅度/时长及从静稳回正或识别通过到页面确认的延迟，不包含原始运动流或稿件。清空记录不重启运动服务、不重置识别器；停止记录后仍可标记本段结果。
- 连接能力、运动数据就绪与数据中断分别处理：`isDeviceMotionAvailable` 不显示成“已连接”，收到有效样本后才确认就绪。原生连接通知只作为提示，不单独中断校准；首帧等待 10 秒、连续数据中断等待 3 秒，运动权限弹窗等待不占用首帧窗口。每次监听使用独立的数据源和回调身份，停止前先失效身份，防止上一轮断连/错误回调影响下一步校准。原生错误仅记录 domain/code 方便真机定位，不记录运动样本。
- 校准使用紧凑动作卡片：右上角大号当前步骤 `1/6`，动作名使用约 28pt 的标题字体，说明约 17pt、辅助提示约 15pt；错误信息收进当前动作卡片内的高亮区，正文使用约 17pt 并增加行距。这些语义字体随系统文字大小调整。动作描述直接放在阶段标题下面，避免重复说明；单步完成后直接显示下一动作和新的步骤数字，已完成记录保留在上方六段进度中。横屏使用等宽、垂直居中的动作/控制两块区域。收到实时数据后才显示“耳机已连接”，未开始时仅显示“戴好 AirPods，点开始”。动作、回正、进度条与最终验证反馈遵循减少动态效果设置。准备阶段平均约 0.65 秒稳定重力，不把一次噪声帧当作佩戴坐标。短暂晃动和数据间断自动重新准备当前动作，单次动作有 30 秒操作时间；回正允许约 5–7° 的舒适偏差。正式播放的点头节奏、侧倾/转头/走动过滤和冷却条件保持独立。
- 每个动作完成后立即检查，错误包含具体动作和可选重做项，重试替换这一条记录并保留其余数据。小幅初始姿态差异通过共同参考平面拟合再正交化；同向动作、点头与侧倾混淆、转头严重偏轴及实际传感器更换仍会明确拒绝。只有六步检查通过才进入试点头，不再把失败状态显示成“六个方向已通过”。
- 个人适配并入六方向之后的末步，界面按 `1/3` 提示三次自然点头，然后独立验证一次；这些动作不切换播放，也不计入播放诊断。学习使用单独的 7° 回正采集带和更严格的静稳端点，允许记录被默认 4° 回正带拒绝的自然动作，不靠生产识别成功与否筛样本。`NodHabitProfile` 用三次摘要的中位数与离散程度检查一致性；当前仅将可靠回正偏差转成 4–7° 的有限容差，幅度与节奏摘要用于一致性检查，不自动降低 6° 下限或放宽 1.85 秒周期上限。最终验证不再更新拟合参数；样本差异太大就保留默认设置，不要求重做六方向。
- 适配可随时选择“使用默认并验证”，取消整轮校准不会写入半成品。旧校准没有 `habit` 字段时沿用默认规则，无需重新校准。来源切换不自动改写持久化校准；运行时根据样本来源清空整次候选，下一次点头须重新静稳并完成完整周期。连续快速切换来源不能拼接静稳或动作，诊断将来源切换与服务错误分别统计。
- 支持性以系统 `isDeviceMotionAvailable` 为准，不按蓝牙名称或型号猜测。需要运动与健身权限，拒绝时提供系统设置入口；无支持设备时允许退出或重试。

合成样本测试覆盖多采样率点头、旋转后的耳机坐标系、冷却、慢低头、抬头、侧倾、转头、模拟走动、数据间断、非法值、传感器切换、六向轴校验、重力与偏航分工及旧设置兼容。模拟器只验证引导/取消/无硬件和现有播放交互，不能验证真实耳机的识别率、误触率、佩戴差异与断连恢复。上线前应在真机上采集对照数据，覆盖坐姿口播、普通说话点头、不同步频走路、转头、单耳/双耳切换和重新佩戴；单靠惯性传感器无法百分之百区分有意控制与相同形态的自然点头。

DEBUG 专用 `-simulateNodCalibration` 使用合成运动数据驱动原生界面，验证六步、单项重试和最终试点头流程；`-calibrationBadUpOnce` 只在该测试模式下模拟一次错误抬头。模拟数据源不编译进 Release，不作为真实 AirPods 验收证据。

`-simulateEarHandoff` 在播放演示流中模拟由左耳切到右耳，验证无须重做校准便能继续开始/暂停。

`-simulateNodPlayback` 配合该测试源，在离开设置后合成点头，验证实际播放与暂停；`-simulateLargeNodCalibration` 模拟 46° 校准和 20° 最终验证。加 `-simulateNaturalNodPlayback` 时，播放控制交替使用 8°/1.2 秒和 30°/0.8 秒点头，含回正偏差及按 10cm 旋转半径估算的切向加速度；这些物理简化样本仅用于回归，不能代替真实耳机记录。配合 `-simulateNodRestShift` 时，播放流在首次进入待命后先抬高 5° 并停稳，再做两次点头，覆盖校准保存、基准重定位、实际开始与暂停的完整回归。

RunLoop 排查：`CADisplayLink.add(to: .main, forMode: .common)` 是向常见模式注册，不是在 `.common` 模式下运行 RunLoop。若真机出现 `invalid mode 'kCFRunLoopCommonModes' provided to CFRunLoopRunSpecific`，应在 Xcode 添加符号断点 `_CFRunLoopError_RunCalledWithInvalidMode` 并查看触发时的调用栈，才能区分工程间接调用与系统框架来源；不能只凭一行日志修改这条合法的显示链接注册。

列表挂载时机：原生列表仅在进入窗口且宽高有效后提交待处理快照；离屏期间合并到最新一版，重新挂载后提交。挂载／尺寸变化回调异步合并，避免在 UIKit 布局栈内重入；快照完成回调在强制布局前再次检查窗口与视图身份。销毁时清理 delegate、dataSource 与排队动作。原有侧滑结束后原子重建、可见行锚定及局部刷新继续保留。此项修正应用自身的过早布局风险，不代表已证明用户日志中 dataSource 为 null 的 UITableView 由该调用产生，也不代表键盘／剪贴板服务日志已修复。

列表更新优化：`ScriptLibraryState` 只缓存最近一组筛选/排序结果和不可变行快照。缓存键包含当前稿件字段、搜索、筛选、排序与摘要；每次检查仍读取 SwiftData 字段，编辑、撤销或未改变修改时间的更新也会失效。选择状态与页面工具状态不参与缓存键。缓存只保存排序后的 ID，操作时解析当前模型，避免跨上下文使用旧对象。`NativeScriptList` 对同序行逐项判断内容、选择、高亮、速度与摘要依赖，无变化时跳过快照提交；顺序变化继续使用滑动结束后的原子重建与可见行锚定，保留防重叠措施。这些改动减少状态更新期间的工作，不代表已验证真机持续滚动帧率改善。
