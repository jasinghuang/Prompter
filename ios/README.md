# 提词器 · iOS 原生版

SwiftUI 界面、SwiftData 本地存储、TextKit 2 / CADisplayLink 提词引擎。Web PWA 与 iOS 各自构建；iOS 保留原来的黑金配色、细金边卡片和胶囊控件。

## 构建

最低系统 iOS 17.0。安装 Xcode 和 XcodeGen 后：

```bash
cd ios
xcodegen generate
open Prompter.xcodeproj
```

工程由 `project.yml` 生成。真机运行需在 Xcode 中选择自己的签名 Team；模拟器可以关闭签名构建。

## 稿件列表与滚动

列表使用系统 `List` 和 `swipeActions`。分类标题与稿件共用一个扁平行序列，稿件跨分类时保持全局 UUID 身份；分类标题为不吸顶的实底行，分组变化不继承滑动收起动画。卡片内部没有 `DragGesture`，竖向滚动由原生列表仲裁，避免“在拖动回调里 return，但识别器仍阻止滚动”的问题。

- 标题栏“新建稿件”使用金色药丸文字按钮；搜索下方左侧使用原生收纳菜单选择全部、星标或文件夹，右侧保留上下箭头排序入口。排序依据为时间（最近修改）、标题、字数，并分别提供升序/降序；排序只作用于对应的星标/拍摄分层内。卡片外观与直接操作保持原样。
- 左滑揭示“删除”，删除后保留 8 秒撤销；关闭 full swipe，降低误删。
- 右滑标记/取消已拍摄；已拍稿件沉到对应分层。
- 点正文开始提词；编辑按钮独立于正文按钮；底部按日期、字数、时长、文件夹、星标排列，文件夹和星标可直接点击；左右滑动提供拍摄标记和删除。
- 长按进入多选，底部操作栏支持全选、移动、批量删除。
- 播放页左侧依次展示返回、时间状态、前置镜子；右侧依次展示拍摄标记、设置；轻点正文播放或暂停，底部仅保留字号和速度参数；速度按 1 字/分调节；窄屏分两行且滑杆等长、左右对齐，宽屏并排且速度滑杆更长。点击左上时间回到顶部并暂停、计时归零，读完后在时间下方提示该操作。
- “读完以后”使用与自动暂停相同的分段选项：停在末尾、回到开头、标记并返回。仅卡片左滑出现的删除操作使用主题金色；顶部清空、批量删除及确认按钮保留危险操作红色，确认和 8 秒撤销流程保留。

## 保存、删除与撤销

- 编辑器提供“完成”，同时在文字变更 500ms 后和进入后台时保存。
- 新建稿件的多次自动保存复用同一条记录；没有修改的稿件不更新时间。
- 删除使用 `Script.deletedAt` 内部标记支持短时撤销及旧库兼容；不提供最近删除页面或恢复入口。
- 底部撤销提示保留 8 秒，只撤销最近一次单篇或批量删除。撤销和多选操作条只在对应状态下出现，列表没有常驻底部菜单。
- 旧库兼容所需的内部删除标记保留，后台清理过期标记记录；界面不承诺长期恢复。
- 编辑器直接展示拆分方式和自动暂停；“智能拆分”与拆分方式同一行展示，按钮只显示操作名、不显示篇数；点击后保存当前内容、创建片段并替换原稿，无预览或二次确认；列表不保留原稿。
- 重要数据写入显式保存并反馈失败；存储打不开时提供重试，保留原存储文件。

## 列表入口

顶部保留清空全部和新建；清空需要确认，可在 8 秒内撤销。移除导入、备份、最近删除的底部工具栏及对应页面。旧 JSON 数据解析和兼容逻辑保留在 MigrationService，当前界面不再提供导入与备份入口。

## 验证

### AirPods 点头控制

播放页设置中提供开关，默认关闭。首次开启依次校准低头、抬头、左右歪头、左右转头，随后在最后一步记录三次自然点头，再用一次独立点头验证后保存。可选择“使用默认并验证”跳过个人适配，无需重做六方向。歪头指脸仍朝前、耳朵靠近同侧肩膀，转头指脸朝向左右两边；不要求耳朵碰到肩膀。取消首次校准不会开启；重新校准取消时保留原配置。更换耳机后识别不顺手时，用户可自行选择重新校准。校准记录舒适动作幅度和耳机坐标轴，不是颈椎活动范围的医学测量。

- 原生 `CMHeadphoneMotionManager` 提供融合运动数据；只在播放页符合条件时监听。设置、化妆镜、操作引导、后台与离开页面都会暂停识别；校准在首次点击开始后维持同一条运动流，直到退出或验证完成。动作之间只更换处理器，丢弃等待期间的动作样本，避免每步重启后数据源和参考坐标变化。
- `HeadMotion.swift` 是纯值类型算法。重力向量通过投影后的 `atan2` 计算有符号点头/侧倾角，不使用欧拉角，也不长期积分角速度。重力不能测偏航；转头校准用短时相对四元数和角速度，运行时用绕重力的角速度排除转头。
- 一次有效点头需要：约 0.45 秒稳定准备 → 至少 6° 低头 → 反向回正并短暂停留；候选约 0.26–1.85 秒内完成，低头段不超过 0.95 秒。六方向校准用于辨认坐标与舒适上限，不再以低头校准幅度的 45% 作为控制门槛（原先 46° 校准会要求每次控制至少 12°）。回正允许约 4–7° 的有限偏差，同时校验静稳端点与点头轴角速度占比。明显侧倾/转头、走动、碰撞、数据丢失及传感器切换仍否决候选。
- 待命基准允许有条件地重新定位：仅在 armed、没有点头候选时，角速度低于 0.12rad/s、用户加速度低于 0.04g，重力方向在约 0.8° 范围内连续稳定 0.65 秒后更新。单次变化不超过 8°、侧倾不超过 6°，相对本次进入待命时的基准累计不超过 12°；小于 1.5° 的微量跟随同样受累计上限约束。检测到低头即冻结，手动重置、缺帧、走动或传感器变化均重新准备。识别后的冷却准备新一轮基准，不改变持久化的六向校准轴。修复先抬高 5–8° 停稳、再小幅点头相对旧基准不足而漏判的问题。
- 点头幅度上限随已学到的舒适幅度变化，不再用固定 36° 上限否决较大点头。38° 起始姿态限制只检查中立基准，不能应用到点头全过程；否则已校准 46° 的动作依旧会在进行途中被清除。点头中的旋转会产生用户加速度，不再用单帧 0.12g 清除完整动作；保留 0.45g 碰撞门槛、静稳端点、原生活动分类、偏轴、节奏与数据连续性检查。触发后的 0.85 秒冷却同时收集静稳数据，不再等冷却结束才开始准备；点头触发播放切换不会再次调用手动重置。手动点击/拖动单独取消排队事件并抑制 0.35 秒，之后重新准备。
- 回正静稳窗口最多 200ms，仅累加两端采样都满足角速度 <0.35rad/s、加速度 <0.07g 的区间，累计至少 100ms；允许其中一次、采样估计累计不超过 40ms 的轻微扰动（角速度 <0.55rad/s、加速度 <0.10g），扰动和首次恢复区间均不算静稳，最后还须连续静稳至少 40ms。超过预算、第二次扰动或超出回正带会重新建立窗口；碰撞、走动、偏轴、传感器变化、非法值与真实缺帧继续中断候选。完整动作 1.85 秒截止和 6° 门槛不变，不延长动作来等待通过。诊断导出 `toleratedReturnDisturbanceMs` 为该次响应窗口容忍的扰动区间估计值。已有校准兼容，界面没有新增控件。
- 开启后播放页暂停时在左上显示真实待命状态（等待静止、就绪、等待回正、走动等），只有检测器已进入 armed 才显示已就绪；播放时收起常驻状态，避免遮挡正文。有效点头直接切换播放并提供轻触反馈，不显示开始/暂停文字浮层。设置、化妆镜和后台仍暂停识别。
- iOS 18 及以上且耳机支持时，同时使用原生 `CMHeadphoneActivityManager` 的步行/跑步分类作为额外否决条件。iOS 17 或不支持活动分类的耳机保留加速度、角速度、静止与节奏过滤；活动分类本身可能延迟，不能取代这些逐样本保护。
- 数据处理在串行后台队列执行，UI 只接收离散事件与低频连接心跳。运动样本不写文件、不上传，只持久化校准参数。失败候选输出一次本机结构化诊断（原因、峰值幅度、时长，不含原始采样），设置中保留上次失败原因，成功识别后清除；关闭设置或暂停识别不会抹掉这条诊断。连接中断不会切换播放状态；重连后重新等待静止。播放检测期间换耳或换耳机后沿用已有轴与个人设置，清空候选、滤波和静稳窗口，重新停稳后恢复；不强制重新校准，也不把来源变化报告成断开。六方向校准与最终适配采集期间仍保持同一来源，避免混合坐标。
- 设置里的“点头诊断”可主动开启本次测试记录，默认不记录。`NodDiagnostics` 将识别通过、页面实际切换、页面未接收、候选拒绝和服务异常分别统计。记录开启时逐帧检查状态，仅在状态变化时增加事件，补足 0.5 秒界面心跳之间的短暂晃动；等待静止、冷却、手动操作后重新准备等状态不自动算作漏判。校准与最终试点头不计入播放统计。
- 测试时先开启记录，关闭诊断和设置回到正文；未响应后可回到诊断手动标记，“上次是误触”仅关联最近一次已实际切换的点头，支持撤销。未响应标记保留进入设置前的最近观察状态和时间，只作参考，不断言为漏判原因。识别器不能知道用户的全部动作意图，界面和导出均不计算成功率。
- 诊断仅在本次播放页面内存中保留，离开页面后释放，不自动保存或上传；累计计数覆盖本段记录，事件保留最近 128 条、可撤销手动标记保留最近 32 条，最近实际响应单独保留以便关联误触。用户通过系统分享导出 JSON 文本，包含原因、状态估计时长、动作幅度/时长及从静稳回正或识别通过到页面确认的延迟，不包含原始运动流或稿件。清空记录不重启运动服务、不重置识别器；停止记录后仍可标记本段结果。
- 连接能力、运动数据就绪与数据中断分别处理：`isDeviceMotionAvailable` 不显示成“已连接”，收到有效样本后才确认就绪。原生连接通知只作为提示，不单独中断校准；首帧等待 10 秒、连续数据中断等待 3 秒，运动权限弹窗等待不占用首帧窗口。每次监听使用独立的数据源和回调身份，停止前先失效身份，防止上一轮断连/错误回调影响下一步校准。原生错误仅记录 domain/code 方便真机定位，不记录运动样本。
- 校准使用紧凑动作卡片：右上角大号当前步骤 `1/6`，动作名使用约 28pt 的标题字体，说明约 17pt、辅助提示约 15pt；错误信息收进当前动作卡片内的高亮区，正文使用约 17pt 并增加行距。这些语义字体随系统文字大小调整。动作描述直接放在阶段标题下面，避免重复说明；单步完成后直接显示下一动作和新的步骤数字，已完成记录保留在上方六段进度中。横屏使用等宽、垂直居中的动作/控制两块区域。收到实时数据后才显示“耳机已连接”，未开始时仅显示“戴好 AirPods，点开始”。动作、回正、进度条与最终验证反馈遵循减少动态效果设置。准备阶段平均约 0.65 秒稳定重力，不把一次噪声帧当作佩戴坐标。短暂晃动和数据间断自动重新准备当前动作，单次动作有 30 秒操作时间；回正允许约 5–7° 的舒适偏差。正式播放的点头节奏、侧倾/转头/走动过滤和冷却条件保持独立。
- 每个动作完成后立即检查，错误包含具体动作和可选重做项，重试替换这一条记录并保留其余数据。小幅初始姿态差异通过共同参考平面拟合再正交化；同向动作、点头与侧倾混淆、转头严重偏轴及实际传感器更换仍会明确拒绝。只有六步检查通过才进入试点头，不再把失败状态显示成“六个方向已通过”。
- 个人适配并入六方向之后的末步，界面按 `1/3` 提示三次自然点头，然后独立验证一次；这些动作不切换播放，也不计入播放诊断。学习使用单独的 7° 回正采集带和更严格的静稳端点，允许记录被默认 4° 回正带拒绝的自然动作，不靠生产识别成功与否筛样本。`NodHabitProfile` 用三次摘要的中位数与离散程度检查一致性；当前仅将可靠回正偏差转成 4–7° 的有限容差，幅度与节奏摘要用于一致性检查，不自动降低 6° 下限或放宽 1.85 秒周期上限。最终验证不再更新拟合参数；样本差异太大就保留默认设置，不要求重做六方向。
- 适配可随时选择“使用默认并验证”，取消整轮校准不会写入半成品。旧校准没有 `habit` 字段时沿用默认规则，无需重新校准。来源切换不自动改写持久化校准；运行时根据样本来源清空整次候选，下一次点头须重新静稳并完成完整周期。连续快速切换来源不能拼接静稳或动作，诊断将来源切换与服务错误分别统计。
- 支持性以系统 `isDeviceMotionAvailable` 为准，不按蓝牙名称或型号猜测。需要运动与健身权限，拒绝时提供系统设置入口；无支持设备时允许退出或重试。

合成样本测试覆盖多采样率点头、旋转后的耳机坐标系、冷却、慢低头、抬头、侧倾、转头、模拟走动、数据间断、非法值、传感器切换、六向轴校验、重力与偏航分工及旧设置兼容。模拟器只验证引导/取消/无硬件和现有播放交互，不能验证真实耳机的识别率、误触率、佩戴差异与断连恢复。上线前应在真机上采集对照数据，覆盖坐姿口播、普通说话点头、不同步频走路、转头、单耳/双耳切换和重新佩戴；单靠惯性传感器无法百分之百区分有意控制与相同形态的自然点头。

DEBUG 专用 `-simulateNodCalibration` 使用合成运动数据驱动原生界面，验证六步、单项重试和最终试点头流程；`-calibrationBadUpOnce` 只在该测试模式下模拟一次错误抬头。模拟数据源不编译进 Release，不作为真实 AirPods 验收证据。

`-simulateEarHandoff` 在播放演示流中模拟由左耳切到右耳，验证无须重做校准便能继续开始/暂停。

`-simulateNodPlayback` 配合该测试源，在离开设置后合成点头，验证实际播放与暂停；`-simulateLargeNodCalibration` 模拟 46° 校准和 20° 最终验证。加 `-simulateNaturalNodPlayback` 时，播放控制交替使用 8°/1.2 秒和 30°/0.8 秒点头，含回正偏差及按 10cm 旋转半径估算的切向加速度；这些物理简化样本仅用于回归，不能代替真实耳机记录。配合 `-simulateNodRestShift` 时，播放流在首次进入待命后先抬高 5° 并停稳，再做两次点头，覆盖校准保存、基准重定位、实际开始与暂停的完整回归。

RunLoop 排查：`CADisplayLink.add(to: .main, forMode: .common)` 是向常见模式注册，不是在 `.common` 模式下运行 RunLoop。若真机出现 `invalid mode 'kCFRunLoopCommonModes' provided to CFRunLoopRunSpecific`，应在 Xcode 添加符号断点 `_CFRunLoopError_RunCalledWithInvalidMode` 并查看触发时的调用栈，才能区分工程间接调用与系统框架来源；不能只凭一行日志修改这条合法的显示链接注册。
